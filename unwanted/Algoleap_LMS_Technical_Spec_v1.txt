1. Overview & Goals
The Algoleap Lead Management System (LMS) is an internal tool for the sales and client-facing teams. It helps them capture new client opportunities, track them through a sales pipeline, and collaborate across the Executive, Practice Leader, Client Manager, Team Member, and Administrator roles.
This document is written for a developer who is new to full-stack development. It assumes you know basic JavaScript and have used React or Node.js in a tutorial before, but have not yet built and deployed a real application. Every section explains not just what to do, but why.
1.1 Primary Goals of v1
Replace ad-hoc spreadsheets and email threads with a single source of truth for leads.
Allow Executives, Practice Leaders, and Client Managers to create and manage leads.
Store structured information about Accounts and Contacts tied to those leads.
Support file attachments (proposals, SOWs, MSAs) on each lead.
Send email notifications when leads are assigned or their stage changes.
Allow lead assignment and reassignment between team members.
Provide a configurable permissions system so administrators can tune access without code changes.
1.2 Non-Goals for v1
These are good ideas, but they're explicitly out of scope for the first release. Keep the MVP small so you can actually ship it.
Public website, customer-facing portal, or external form submissions.
Sales forecasting, AI scoring, or ML recommendations (can be added post-v1).
Mobile app — the web app is responsive, but no native iOS/Android.
Deep integrations with external CRMs like Salesforce (import/export via CSV only in v1).
SSO (Google/Microsoft) — we start with email + password; SSO is a v2 task.
1.3 Expected Scale
About 25 active internal users. A small team. This matters because it means:
PostgreSQL free tier will handle the database comfortably.
Vercel + Render free tiers are sufficient for hosting.
You do not need Redis, message queues, or microservices.
Simplicity and clarity matter more than scale optimizations.

3. User Roles & Personas
Five roles are shipped by default. The permissions attached to each role are fully configurable — see Section 8.
3.1 Executive
A senior leader who views the full pipeline across all practices and occasionally creates strategic leads. Example: Rahul Desai, Head of Sales. Primary need: visibility across everything.
3.2 Practice Leader
Owns a service line (e.g., AI & Automation, Service Management). Reviews and edits all leads within their practice, assigns team members, and signs off on proposals. Example: Anita Krishnan, Head of AI & Automation.
3.3 Client Manager
The most active user type. Creates and manages leads for the accounts they own. Uploads SOWs and pricing documents. Moves leads through stages. Example: Priya Menon.
3.4 Team Member
Delivery-side team who needs read-only access to leads they are tagged on, so they can prep for engagement kickoff. They do not create or edit leads.
3.5 Administrator
Manages users, roles, and the permissions matrix. Typically one or two IT or operations people. Has the highest level of access to the system configuration, not necessarily to business data.
Beginner tip: Roles are just labels. What each role can actually do is controlled by the permissions matrix in Section 8. Keep roles conceptual and permissions granular — that combination is called Role-Based Access Control (RBAC).

7. Database Design
This is the most important section. Get the data model right, and everything else is mechanical. Get it wrong, and every feature fights you.
7.1 Tables at a Glance

Purpose

People who log in. Stores email + password hash + role.

Named role like 'Client Manager'. Default 5, extensible.

Atomic permissions like 'leads.create'. Reference list.

7.2 Relationships Map
One account has many contacts. One account has many leads. One contact can be attached to many leads (via a primary_contact_id on leads). One user owns many leads. One lead has many attachments and many activity entries.

8.3 How Permission Checks Work at Runtime
On every API request, a middleware function checks two things: (1) is the user logged in, and (2) does the user's role have the required permission. If either fails, return HTTP 403.
// apps/api/src/middleware/permit.js const { prisma } = require('../lib/prisma');  function permit(requiredKey) {   return async (req, res, next) => {     const userId = req.user?.id;     if (!userId) return res.status(401).json({ error: 'Not signed in' });      const user = await prisma.user.findUnique({       where: { id: userId },       include: {         role: {           include: { permissions: { include: { permission: true } } }         }       }     });      const keys = user.role.permissions.map(rp => rp.permission.key);     if (!keys.includes(requiredKey)) {       return res.status(403).json({ error: 'Forbidden', missing: requiredKey });     }     next();   }; }  module.exports = { permit };
Use it on any route:
// apps/api/src/routes/leads.routes.js const { permit } = require('../middleware/permit');  router.post('/leads', auth, permit('leads.create'), createLead); router.patch('/leads/:id', auth, permit('leads.edit_own'), editLead); router.delete('/leads/:id', auth, permit('leads.delete'), deleteLead);
Scope matters: 'leads.edit_own' alone isn't enough — the handler must ALSO verify the current user is the owner. The permission says 'you're allowed to edit leads you own'; the controller must enforce 'this lead you're editing IS yours'.

11. File Uploads (Attachments)
We use Supabase Storage because it's free up to 1 GB and has a simple JS SDK. The actual file lives in Supabase; our DB only stores metadata and a URL.
11.1 Setup
In Supabase dashboard, create a Storage bucket named 'lead-attachments'.
Make it private (not public). We'll generate signed URLs for downloads.
Copy SUPABASE_URL and SUPABASE_SERVICE_KEY to apps/api/.env.
npm install @supabase/supabase-js
11.2 Upload Endpoint
// apps/api/src/routes/uploads.routes.js const multer = require('multer'); const { createClient } = require('@supabase/supabase-js'); const upload = multer({ limits: { fileSize: 10 * 1024 * 1024 } }); // 10 MB  const supabase = createClient(   process.env.SUPABASE_URL,   process.env.SUPABASE_SERVICE_KEY );  router.post('/leads/:id/attachments',   auth,   permit('leads.upload_attachment'),   upload.single('file'),   async (req, res) => {     const { id: leadId } = req.params;     const { originalname, mimetype, size, buffer } = req.file;     const path = `${leadId}/${Date.now()}-${originalname}`;      const { data, error } = await supabase       .storage.from('lead-attachments')       .upload(path, buffer, { contentType: mimetype });      if (error) return res.status(500).json({ error: error.message });      const attachment = await prisma.leadAttachment.create({       data: {         leadId,         fileName: originalname,         fileSize: size,         mimeType: mimetype,         storageUrl: data.path,         uploadedById: req.user.id       }     });     res.json(attachment);   });
Security note: Never trust the file extension. Validate the MIME type on the server. For v1, allow only: application/pdf, application/vnd.openxmlformats-officedocument.wordprocessingml.document, application/vnd.openxmlformats-officedocument.spreadsheetml.sheet, image/png, image/jpeg.

// apps/api/src/services/leadStateMachine.js const TRANSITIONS = {   NEW:         ['QUALIFIED','LOST','ON_HOLD'],   QUALIFIED:   ['PROPOSAL','LOST','ON_HOLD'],   PROPOSAL:    ['NEGOTIATION','LOST','ON_HOLD'],   NEGOTIATION: ['WON','LOST','ON_HOLD'],   ON_HOLD:     ['NEW','QUALIFIED','PROPOSAL','NEGOTIATION'],   WON:         [],   LOST:        [] };  function canTransition(from, to) {   return TRANSITIONS[from]?.includes(to) ?? false; } module.exports = { canTransition };

14. Security Basics
A short list. Do all of these — skipping any one creates a real risk.
Hash passwords with bcrypt. Never store plain text. Use a cost factor of 10 or higher.
JWT secret must be at least 32 random characters. Rotate if leaked.
Enable CORS only for your known frontend origin, not '*'.
Validate every request body with Zod before using the values. Reject unknown fields.
Rate-limit /auth/login to 5 attempts per minute per IP. Use express-rate-limit.
Use HTTPS for all deployed environments. Free via Vercel / Render.
Don't commit .env files. Add .env to .gitignore immediately.
Sanitize file names before saving. Strip '../' and special characters.
Limit file upload size at both the middleware (Multer) and the bucket level.
Permission check on EVERY mutating endpoint. Even if the UI hides the button, the API must say no.
Golden rule: The frontend is never the source of truth for security. A user can always craft API requests manually. Every meaningful check must happen on the server.

Term
Meaning
RBAC

Object-Relational Mapper. Lets you write DB queries in JavaScript instead of SQL.
